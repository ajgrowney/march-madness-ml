Target outputs

Your repo should produce these artifacts for one season:

teams.json
Purpose: lightweight search/index for the site.

features/base.json
Purpose: inference-ready feature vectors keyed by team ID.

ts/{teamId}_{season}.json
Purpose: rich team detail payloads for Team Insights.

brackets/{season}.json
Purpose: seed map, slots, regions, dependency graph.

models/manifest.json
Purpose: tells the site what reference models or runtime configs exist.

TeamSeasons_{season}.csv
Purpose: keep as the canonical training/export matrix for offline analysis.

Historical training export contract

The browser training path now has a separate historical export contract alongside the serving artifacts.

Generated files

data/web/features/{season}/historical_v1.json
Purpose: season feature store used to build browser-side matchup vectors.

data/web/training/historical_v1/{season}.json
Purpose: season matchup training dataset in diff format.

data/web/training/manifest.json
Purpose: discovery file for exported seasons, feature order, label meaning, and file paths.

Feature store shape

Path:
data/web/features/{season}/historical_v1.json

Required top-level keys:
season
feature_set
feature_order
teams

Rules:
feature_set is currently historical_v1
feature_order is the canonical model-input order
teams is keyed by TeamID string
every team entry must contain one numeric value per feature in feature_order

Current feature order:
Seed
WinPct
SOS
SOV
selection_ordinal_last
AdjOE_mean
AdjDE_mean
AdjNE_mean
FG%_mean
FG3%_mean
FT%_mean

selection_ordinal_last is normalized across eras:
pre-2019 seasons map to the last RPI-style ordinal
2019+ seasons map to the last NET-style ordinal

Training file shape

Path:
data/web/training/historical_v1/{season}.json

Required top-level keys:
season
feature_set
feature_order
format
include_regular_season
include_tournament
label_definition
examples

Rules:
format is diff only
each real game is exported twice for directional labels
label_definition uses 0 = team_1_win and 1 = team_2_win

Each example requires:
season
source
day_num
team_1_id
team_2_id
x
y

Example rules:
source is regular_season or tournament
x is an ordered numeric vector aligned to feature_order
y is 0 or 1
len(x) must equal len(feature_order)

Training manifest shape

Path:
data/web/training/manifest.json

Required top-level keys:
generated_at
feature_set
feature_order
format
include_regular_season
include_tournament
label_definition
seasons
feature_files
training_files

Rules:
seasons lists every exported historical season
feature_files[season] points to that season's feature store
training_files[season] points to that season's matchup dataset
the website should use this file as the only discovery entrypoint for browser training data

Website readiness checklist

The website is ready for the full export if it can:

1. Load data/web/training/manifest.json first and trust feature_order from the manifest instead of hardcoding columns.
2. Fetch season files through feature_files[season] and training_files[season].
3. Build vectors from feature_order only, not from object key iteration.
4. Respect label_definition so browser training uses the same target meaning as Python.
5. Treat selection_ordinal_last as a normalized field name, not as always-NET.
6. Handle Seed = 17.0 as the default non-tournament-team value.
